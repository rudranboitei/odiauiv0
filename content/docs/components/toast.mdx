## Installation

```bash
npx shadcn@latest add https://odiaui.xyz/r/toast.json
```

Colours come only from shadcn theme tokens, so toasts follow your theme automatically in light and dark mode.

## Setup

Mount `<Toaster />` once in your root layout, then fire toasts from a manager:

```tsx
import { Toaster } from "@/components/ui/toast";

// in your layout
<Toaster />;
```

```tsx
import { toast } from "@/components/ui/toast";

toast.add({
  title: "Saved",
  description: "Your changes have been saved.",
  type: "success",
});
```

For isolated demos or local managers, use `createToastManager()` and pass it to `<Toaster toastManager={manager} />`.

## Tips

- Use theme tokens only (no hardcoded status colors) so toasts work in light and dark mode.
- Keep a visible close button or rely on swipe-to-dismiss for every toast.
- Toast content is announced with `role="status"` for screen readers.
- Use stable IDs with `manager.update(id, ...)` / `manager.close(id)` for persistent or evolving toasts (progress, offline/online, promise flows).

## API Reference

### Toaster

Mount once to render the toast viewport and list.

| Prop           | Type                                                                                              | Default          | Description                            |
| -------------- | ------------------------------------------------------------------------------------------------- | ---------------- | -------------------------------------- |
| `toastManager` | `ToastManager`                                                                                    | shared manager   | Manager instance used by this toaster. |
| `position`     | `"top-left" \| "top-center" \| "top-right" \| "bottom-left" \| "bottom-center" \| "bottom-right"` | `"bottom-right"` | Viewport position.                     |

### toast / createToastManager / useToastManager

`toast` is the shared manager. `createToastManager()` creates an isolated manager. Common methods: `add`, `update`, `close`, and `promise`. `useToastManager()` reads active toasts inside the provider.

### Toast data options

Per-toast overrides can be passed via `data`:

- `watermark`: `"none" | "deula" | "chakra"` (default behavior depends on toast; demos often use `"none"` for clean product patterns)
- `content`: custom React content for fully custom toast layouts
- `contentClassName`: extra classes for the content wrapper when using custom content
- `hideClose`: hide the default close button in the standard layout

### Toast parts

`Toast`, `ToastContent`, `ToastTitle`, `ToastDescription`, `ToastAction`, and `ToastClose` are exported for composing custom toast UIs. Triggers/actions use Base UI’s `render` prop pattern where applicable.
